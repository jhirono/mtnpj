## Spacing Scale

The project uses Tailwind's default spacing scale. All spacing must use multiples of 4px.
The FilterPanel currently uses values from the 4px scale exclusively.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`) | Icon gaps, tight inline padding |
| sm | 8px (`gap-2`, `p-2`, `py-2`, `mt-2`) | Compact element spacing — matches existing FilterPanel rhythm |
| md | 8px (`gap-2`, `p-2`, `mr-2`) | Picker button internal padding, label gaps |
| lg | 12px (`p-3`, `gap-3`, `space-y-3`) | FilterPanel container padding — existing pattern |
| xl | 16px (`p-4`) | Route card padding — existing pattern |
| 2xl | 24px (`gap-6`) | Layout column gaps |
| 3xl | 32px | Page-level spacing — not used in FilterPanel |

Exceptions:
- **12px (`p-3`, `gap-3`, `space-y-3`):** pre-existing FilterPanel spacing pattern. Although 12px is not in the standard set (4, 8, 16, 24, 32, 48, 64), changing it to 16px would require restyling the entire FilterPanel container beyond this phase's scope. New elements introduced in this phase must not add additional non-standard values.
- **36px (`h-9`):** minimum touch target height per WCAG 2.5.5 recommendation. No value in the standard set satisfies the 36px minimum without exceeding it to 40px (which is not in the standard set either) or dropping to 32px (which fails WCAG touch target guidance). Declared as a justified accessibility exception.
- Active badge circles in accordion headers: fixed `w-4 h-4` (16px) — existing pattern, preserve.

Source: Measured from `FilterPanel.tsx` class inventory.

## Typography

The project declares a single root font size and weight. FilterPanel uses `text-sm` throughout.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / filter labels | 14px (`text-sm`) | 400 (`font-normal`) | 1.5 (root default) |
| Section headings | 14px (`text-sm`) | 500 (`font-medium`) | 1.5 |
| Picker button labels | 14px (`text-sm`) | 500 (`font-medium`) | 1 (single line, no wrap) |
| Badge counts | 12px (`text-xs`) | 500 (`font-medium`) | 1 (fixed height circle) |

Rules:
- Use exactly these 2 weights: 400 (labels, options) and 500 (headings, picker buttons, interactive labels, badge counts).
- No heading larger than `text-sm` inside FilterPanel — consistent with existing pattern.
- Picker button labels MUST NOT wrap. If the 5-button row overflows at viewport < 320px,
  truncate with `truncate` class (see Overflow section below).

Source: `climbing-search/src/index.css` (root font-weight: 400, line-height: 1.5),
`climbing-search/src/components/FilterPanel.tsx` (text-sm throughout).

Accent must NOT be used for: inactive picker buttons, Sort By label, section headings,
checkbox states (browser default), or any element not in the list above.

**Inactive picker button:**
- Light: `bg-gray-100 text-gray-700 hover:bg-gray-200`
- Dark: `dark:bg-gray-700 dark:text-gray-300 dark:hover:bg-gray-600`

Location: FilterPanel, above Grade Filter section. Not inside an accordion.

unlikely but must be handled gracefully. Do NOT stack buttons vertically.

- `<select>` options populate from the active system's grade list (not SIMPLE_GRADES for non-YDS)
- Default values per system:
  - YDS: min = "5.10a", max = "5.11a" (existing default)
  - V: min = "V0", max = "V5"
  - Aid: min = "A0", max = "A3"
  - Ice: min = "WI1", max = "WI4"
  - Mixed: min = "M1", max = "M6"

### Sort By Row (reduced)

Remove 4 specialty options from `<select>`. Keep exactly 4 options in this order:
1. Grade
2. Stars
3. # of Votes
4. Left to Right

No visual structure change — same inline flex row as today.

## Interaction Contracts

### System Switch
1. User clicks an inactive picker button.
2. Active button transitions: previous active loses `bg-blue-600`, gains `bg-gray-100`.
   New active gains `bg-blue-600 text-white`. Transition: `transition-colors` (150ms).
3. Grade filter checkbox unchecks immediately (no animation).
4. Grade filter min/max selects re-populate with new system's grade list.
5. Grade filter min/max reset to system defaults (see above).
6. If Sort By is set to "Grade": polymorphic sort now routes to the new system's
   `extract*GradeNumeric` function automatically. No sort option change needed.
7. API call fires with updated `grade_system` param; previous `grade_list` is dropped.

Source: `05-CONTEXT.md` D-07, D-11.

### Grade Filter Enable (non-YDS)
1. User checks Grade Filter checkbox.
2. Min/max selects appear (same layout as YDS).
3. On change, client slices the active system's ordered grade array from minIdx to maxIdx+1,
   joins as comma-separated `grade_list`, sends to API with `grade_system` param.
4. API builds LIKE clauses for each grade in `grade_list`.

### Sort "Grade" Polymorphic
- `gradeSystem === 'yds'`: use `normalizeGrade` + `gradeToNumeric` (existing path)
- `gradeSystem === 'boulder'`: use `extractBoulderGradeNumeric`
- `gradeSystem === 'aid'`: use `extractAidGradeNumeric` (passes both `route_grade` and `route_protection_grading`)
- `gradeSystem === 'ice'`: use `extractIceGradeNumeric`
- `gradeSystem === 'mixed'`: use `extractMixedGradeNumeric`
- Null-last: routes returning `null` sort to bottom in both ascending and descending directions.

Source: `05-CONTEXT.md` D-10, D-12.

## Accessibility Contract

- Picker button container: `role="group"` + `aria-label="Grade System"`
- Each button: `aria-pressed={isActive}` — communicates selected state to screen readers
- Buttons are `<button type="button">` — not radio inputs (segmented button pattern)
- Grade filter checkbox: existing `<input type="checkbox">` pattern, no change
- Sort select: existing `<select>` pattern with `aria-label` if no visible adjacent `<label>`
- Color contrast: `bg-blue-600 text-white` meets WCAG AA (4.5:1 for 14px text)
- Dark mode contrast: `dark:bg-gray-700 dark:text-gray-300` — existing pattern, verified in prior phases
